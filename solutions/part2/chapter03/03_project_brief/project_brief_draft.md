# 초개인용 숏폼 SNS 기획서 초안

학습용 가상 프로젝트입니다. 6개 구성, 인쇄본 10쪽에 대응하는 문단입니다. 페이지가 고정된 파일은 동봉 PDF입니다. 제안·가설과 확인된 메모를 구분했습니다.

## 1. 배경과 문제 정의 — 기획의 출발점

인쇄본 1쪽

이번 초안은 가까운 사람과 짧은 브이로그를 나누는 가상 SNS의 시험 계획입니다. 처음부터 공개 이용자를 모집하는 대신, 초대한 사람과 공유하는 경험이 필요한지 확인하려고 합니다.

출발점은 공개 게시를 부담스러워하는 사용자가 있을 것이라는 가설입니다. 제공 메모에는 인터뷰 결과가 없으므로 이를 확인된 시장 요구로 표현하지 않습니다. 이용자 규모나 성장률도 근거 없이 넣지 않습니다.

문제를 확인할 때에는 언제 영상을 공유하고 싶은지, 누구에게 보여 주려는지, 현재 어떤 점이 불편한지를 물을 수 있습니다. 이는 조사 문항의 제안이며 실제 응답이 아닙니다.

첫 결정은 이 가설을 검증할 가치가 있는지 판단하는 것입니다. 인터뷰 대상과 인원, 조사 담당자는 [확인 필요]입니다. 준비가 끝나기 전에는 서비스 효과를 확정하지 않습니다.

## 1. 배경과 문제 정의 — 이용 상황과 경계

인쇄본 2쪽

메모가 제안하는 이용 상황은 본인의 짧은 일상 영상을 기록한 뒤 초대받은 지인에게 공유하는 것입니다. 영상의 주인과 열람 가능한 사람을 사용자가 이해할 수 있게 안내하는 것을 초안의 중심에 둡니다.

초기 시험 범위에는 영상 업로드, 초대받은 사람에게 공유, 내 영상 삭제만 포함합니다. 광고, 결제, 공개 추천 피드, 실시간 방송은 이번 시험에서 제외합니다. 이 경계는 제공 메모의 범위를 유지한 것입니다.

화면을 더 많이 만드는 것만으로 사용자 문제를 해결했다고 판단하지 않습니다. 공유 대상을 잘못 이해하거나 삭제 결과를 확인하지 못한다면 기본 흐름부터 다시 검토합니다. 이러한 판단은 시험 시 확인할 조건입니다.

영상 길이와 파일 크기의 한도, 초대 방식, 미성년자 사용 범위는 정하지 않았습니다. 관련 기준은 [확인 필요]로 남기고 실제 서비스 정책처럼 단정하지 않습니다.

## 2. 현황 분석 — 현재 자료에서 아는 것

인쇄본 3쪽

현재 제공 자료는 프로젝트 기획 메모 한 개입니다. 사용자의 실제 불편을 보여 주는 인터뷰, 기존 서비스 비교 조사, 비용 견적은 포함되어 있지 않습니다. 따라서 현황 분석의 출발점은 자료의 범위를 명확히 하는 것입니다.

확인할 수 있는 내용은 기획 주제, 첫 시험에서 다룰 기능, 제외할 기능, 네 주의 일정 제안입니다. 담당자와 착수일은 비어 있습니다. 구현이 이미 끝났거나 일정이 승인되었다고 표현하면 안 됩니다.

다음 자료로는 인터뷰 기록과 화면 시험 결과를 제안합니다. 인터뷰 문장은 응답자의 실제 표현과 작성자의 해석을 나눠 적는 편이 좋습니다. 화면 시험에서는 사용자가 어디에서 멈추었는지를 기록할 수 있습니다.

외부 시장 수치와 경쟁 서비스의 기능은 이 초안에 추가하지 않았습니다. 필요하다면 공식 공개 자료를 조사하고 조사일과 근거를 따로 기록해야 합니다. 현재 시장 규모와 경쟁 비교는 [확인 필요]입니다.

## 2. 현황 분석 — 검증해야 할 가설

인쇄본 4쪽

첫 가설은 공개 범위를 제한하면 일상을 공유하는 부담이 줄 수 있다는 것입니다. 두 번째는 짧은 영상 기록이 사용자의 반복 행동에 맞을 수 있다는 것입니다. 둘 다 제공 메모를 바탕으로 정리한 가설이며 확인된 성과가 아닙니다.

사용자에게 공개 범위를 설명한 뒤 스스로 설정해 보게 하는 방법을 제안합니다. 설정한 사람과 실제로 열람 가능한 사람이 일치한다고 이해하는지 확인하면 화면 문구를 고칠 근거를 얻을 수 있습니다.

삭제 동작도 따로 확인합니다. 사용자는 내 화면에서 보이지 않는 것과 공유된 영상이 더 이상 열리지 않는 것을 다르게 받아들일 수 있습니다. 정확한 삭제 범위와 보관 정책은 먼저 정해야 할 [확인 필요] 항목입니다.

검증 결과는 통과 또는 실패 숫자만 남기기보다 상황, 관찰한 행동, 다시 물어볼 내용을 구분해 기록하는 방식을 제안합니다. 참여자 수와 평가 기준은 아직 확정하지 않았습니다.

## 3. 해결 전략 — 첫 시험판의 기능

인쇄본 5쪽

첫 시험판은 사용자가 영상 업로드, 초대한 사람에게 공유, 내 영상 삭제의 세 기능을 끝까지 따라가도록 구성하는 안입니다. 제공 메모에 없는 결제나 공개 추천 기능을 이번 범위에 추가하지 않습니다.

업로드 단계에서는 진행 상태와 실패 시 다시 할 행동을 표시하는 방법을 제안합니다. 네트워크가 끊겼을 때 영상이 이미 올라갔는지 알 수 있도록 결과를 안내해야 하는지 검토합니다. 실제 처리 방식은 구현 전에 정합니다.

공유 단계에서는 현재 선택된 대상이 누구인지 확인하는 화면을 제안합니다. 초대 링크의 유효기간이나 재사용 방식은 정하지 않았습니다. 임의의 숫자를 정책으로 채우지 않고 [확인 필요]로 둡니다.

삭제 단계에서는 삭제할 대상을 확인하고 결과를 안내하는 흐름을 제안합니다. 다른 사람의 저장본까지 지울 수 있다고 약속하지 않습니다. 서버 보관과 복구 범위는 설계 및 운영 책임자가 확인해야 합니다.

## 3. 해결 전략 — 화면과 검토 순서

인쇄본 6쪽

화면 초안은 제공 메모의 두 번째 주 일정에 배치합니다. 화면 수를 성과로 삼기보다 업로드에서 공유, 삭제까지 주요 흐름을 설명할 수 있는지 검토하는 방식입니다. 실제 화면 설계는 후속 작업입니다.

첫 검토에서는 글자와 버튼의 의미를 살펴봅니다. 사용자가 공개 범위나 실패 메시지를 이해하지 못하면 문구를 수정합니다. 사용자에게 기술 구조를 외우게 하기보다 다음 행동을 알 수 있게 하는 것을 제안합니다.

두 번째 검토에서는 모바일에서 주요 동작을 끝낼 수 있는지 확인합니다. 작은 화면에서 공유 대상을 다시 확인할 수 있는지, 업로드 실패 안내가 가려지지 않는지 살펴보는 항목을 제안합니다.

검토 담당자와 승인 방식은 [확인 필요]입니다. 초안에 적힌 검토 순서는 제안이며 이미 수행한 시험이 아닙니다. 실제 의견을 받으면 원문과 수정 내용을 함께 남겨 판단 이유를 확인할 수 있게 합니다.

## 4. 기대 효과 — 효과와 측정 계획

인쇄본 7쪽

기대 효과는 가까운 사람과 일상을 기록할 때 느끼는 부담이 줄 수 있다는 가설입니다. 제공 메모에는 효과를 입증하는 사용자 조사나 운영 데이터가 없습니다. 따라서 증가율과 절감 시간을 성과처럼 제시하지 않습니다.

시험에서는 사용자가 공유 대상을 이해했는지, 업로드 실패 시 다음 행동을 알았는지, 삭제 결과를 설명할 수 있는지를 살펴보는 방법을 제안합니다. 각 항목은 메모에 있는 확인할 사항을 구체화한 것입니다.

기록 양식에는 시험 상황, 사용자의 행동, 어려웠던 점, 수정 제안을 구분할 수 있습니다. 평가 점수와 성공률을 쓰려면 무엇을 성공으로 볼지 먼저 정해야 합니다. 목표 수치와 허용 기준은 [확인 필요]입니다.

결과가 기대와 다르더라도 이를 숨기지 않습니다. 필요성이 확인되지 않으면 기능 추가보다 문제 정의를 다시 검토하는 선택지를 남깁니다. 이 초안은 투자 효과나 매출을 보장하는 문서가 아닙니다.

## 5. 일정과 예산 — 일정 제안

인쇄본 8쪽

제공 메모의 일정은 네 주 제안입니다. 첫 주에는 문제를 확인하고, 둘째 주에는 화면 초안을 만들며, 셋째 주에는 시험판을 만들고, 넷째 주에는 사용성을 확인합니다. 착수일이 없으므로 실제 달력 날짜로 바꾸지 않았습니다.

첫 주의 결과물로 인터뷰 질문과 확인한 문제 목록을 제안합니다. 둘째 주에는 주요 화면 흐름과 미정 항목 목록을 검토할 수 있습니다. 이는 계획을 설명하기 위한 결과물 제안이며 확정된 산출물 규정이 아닙니다.

셋째 주 시험판에서는 세 기능의 연결을 확인합니다. 넷째 주에는 사용자의 어려움과 수정할 내용을 기록하는 방법을 제안합니다. 문제가 남으면 일정을 늘릴지 범위를 줄일지 담당자가 판단해야 합니다.

실제 착수일, 각 주 담당자, 검토일과 승인자는 [확인 필요]입니다. 개발 인원이나 기존 기반이 없으므로 네 주 안에 반드시 완성된다고 약속하지 않습니다. 작업 전에 수행 가능성을 확인해야 합니다.

## 5. 일정과 예산 — 예산 확인 항목

인쇄본 9쪽

예산 한도, 인건비와 서버비는 제공 메모에서 모두 미정입니다. 가상의 견적을 확정 금액처럼 넣지 않습니다. 합계를 내려면 적어도 항목별 금액, 단위, 기간과 포함 범위를 먼저 확인해야 합니다.

확인할 항목으로 제작 인력 투입 범위, 영상 저장과 전송 비용, 시험 운영 기간을 제안합니다. 각 항목은 실제 견적을 받을 때 비교 기준이 될 수 있습니다. 서비스를 선택하거나 계약하는 단계는 이 초안에 포함하지 않습니다.

월 비용과 일회성 제작비를 혼합해 합산하지 않도록 구분하는 양식을 제안합니다. 세금 포함 여부나 비용 산정 기간이 다르면 같은 총액처럼 비교하면 안 됩니다. 제공 자료에는 이 조건도 없습니다.

현재 기획서의 예산 총액은 [확인 필요]입니다. 비용 담당자와 승인 한도도 [확인 필요]입니다. 실제 조건을 받은 뒤 항목별 근거를 붙이고 합계를 검토해야 예산을 의사결정에 사용할 수 있습니다.

## 6. 리스크와 대응 — 승인 전 확인 목록

인쇄본 10쪽

첫 리스크는 이용자가 공유 대상을 잘못 이해할 가능성입니다. 대응으로 대상 확인 화면과 사용성 시험을 제안합니다. 실제 빈도와 영향 수준은 아직 측정하지 않았으므로 숫자나 등급을 확정하지 않습니다.

두 번째는 삭제 범위에 대한 기대가 서로 다른 경우입니다. 삭제 후 어떤 사본이 남을 수 있는지 정책을 확인하고 안내 문구를 검토해야 합니다. 구체적인 보관 기간이나 법적 준수 여부는 근거 없이 쓰지 않습니다.

업로드 실패와 모바일 사용성도 제공 메모의 확인 대상입니다. 실패 시 재시도 방법과 중복 업로드 확인, 작은 화면의 주요 동작 검토를 후속 시험 항목으로 제안합니다. 시험 결과는 아직 없습니다.

승인 전에 문제 가설, 시험 기능 범위, 네 주 일정의 실행 가능성, 예산 근거, 공유와 삭제 정책을 확인해야 합니다. 승인 담당자와 실제 참여자는 [확인 필요]입니다. 이 문서는 검토를 위한 초안이며 확정 운영 계획이 아닙니다.
