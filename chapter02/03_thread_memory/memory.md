# 새 스레드에서 달빛책방 오픈 준비 이어 가기

서울 인사동에서 카페를 겸한 작은 책방을 운영한다고 가정합니다. 가게 정보와 작업 순서를 한 번 알려 준 뒤 새 스레드에서 짧은 문장으로 이어지는지 확인합니다.

1. Codex 설정의 **개인 맞춤 설정**에서 **메모리 활성화** 또는 **로컬 메모리 활성화** 항목을 켭니다. IDE에서 메뉴가 보이지 않으면 연결된 Codex 실행 환경의 메모리 설정을 확인합니다. 제공되는 환경에서는 `/memories`로 현재 대화의 메모리 사용·생성을 확인할 수 있습니다. [공식 안내](https://learn.chatgpt.com/docs/customization/memories)
2. 저장소 밖에 빈 실습 폴더를 만들고 VS Code에서 그 폴더만 엽니다. 이 안내문과 답안은 브라우저로 읽습니다. Codex가 프로젝트 파일에서 가게 정보를 읽지 않도록 이 파일을 작업 폴더에 복사하거나 첨부하지 않습니다.
3. 새 스레드에 아래 문장을 입력합니다.

```text
이번 실습에서는 내가 서울 종로구 인사동에서 ‘달빛책방’이라는
카페를 겸한 작은 책방을 운영한다고 가정해 줘.
우리 책방은 손님에게 다정한 존댓말을 사용해.
앞으로 내가 ‘안녕, 카페 문 열어 줘.’라고 말하면 다음 순서로 오픈 준비를 도와줘.
1. 서울 종로구의 오늘 날씨를 확인해 줘.
2. 그 날씨와 조용한 책방 분위기에 어울리는 음악을 유튜브에서 찾아 하나 골라 줘.
   브라우저를 조작할 수 있으면 영상을 열고 재생해 줘.
   재생할 수 없으면 확인한 영상 링크와 재생 방법을 알려 줘.
3. 오늘 날씨와 음악을 고른 이유를 짧게 설명해 줘.
4. 손님에게 전할 따뜻한 문장을 직접 한 문장 만들고,
   마지막에는 ‘오늘도 좋은 문장 만나세요.’를 붙여 줘.
가게 정보와 이 작업 방식을 다음 대화에서도 참고해 줘.
정보를 확인할 수 없으면 추측하지 말고 먼저 물어봐 줘.
지금은 파일을 수정하거나 별도 파일에 저장하지 마.
날씨 검색과 음악 재생도 아직 시작하지 마.
```

4. 응답을 확인한 뒤 해당 대화를 마칩니다. 메모리는 백그라운드에서 갱신되며 활성 상태이거나 짧은 대화는 생성 대상에서 빠질 수 있습니다. 바로 새 스레드를 열거나 VS Code를 재시작하는 것만으로 반영이 보장되지는 않습니다.
5. 이후 **새 채팅**으로 빈 스레드를 만들고 아래 한 문장만 입력합니다. 기존 대화를 복사하는 분기 기능은 사용하지 않습니다.

```text
안녕, 카페 문 열어 줘.
```

6. 가게 이름·지역·말투·작업 순서가 이어졌는지 [관찰 기록](memory-observation.md)에 적습니다. 가게 이름과 지역을 다시 프롬프트에 넣으면 메모리가 떠올렸는지 구분할 수 없습니다.
7. 날씨 출처의 날짜와 지역, 영상 링크의 제목을 직접 확인합니다. 재생이 시작되지 않으면 제공된 링크에서 재생 버튼을 누릅니다. **메모리 회상 여부와 브라우저 재생 여부는 따로 기록합니다.**

앞뒤 대화는 같은 PC의 같은 Codex 실행 환경에서 진행합니다. ChatGPT 웹 메모리와 로컬 Codex 메모리는 별개이므로 웹에서 메모리를 켰다는 사실만으로 IDE의 메모리도 켜졌다고 판단하지 않습니다. [공식 메모리 저장소 안내](https://learn.chatgpt.com/docs/customization/memories)

## 기억하지 못했을 때

“어느 지역의 카페인가요?”라는 질문이 나오면 이번 시도에서는 회상이 확인되지 않은 것입니다. 메모리 사용·생성 설정을 확인하고 충분한 시간이 지난 뒤 다시 시도합니다. 반복해서 실패하면 그 결과를 그대로 기록합니다. 재시작 횟수나 대기 시간을 성공 조건으로 단정하지 않습니다.

실제 업무를 이어 갈 때는 가게 정보와 작업 순서를 다시 알려 줘도 됩니다. 다만 그 응답은 **추가 정보를 제공한 뒤의 결과**로 기록하고, 메모리 성공 사례로 세지 않습니다.
