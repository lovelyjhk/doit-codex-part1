# 셋째마당 프롬프트

셋째마당(7~10장) 본문에 나오는 프롬프트를 책과 같은 문장으로 모았습니다. 실습 순서대로 한 단계씩 입력하고, 결과 파일을 연 다음 다음 단계로 넘어갑니다.

- 먼저 [시작 안내](README.md)의 작업 규칙을 읽고, 표에 적힌 폴더를 VS Code에서 엽니다.
- `@파일명`은 입력란에 `@`를 입력한 뒤 목록에서 그 파일을 고르라는 뜻입니다. 아직 만들지 않은 결과 파일은 `@` 없이 이름만 적혀 있습니다.
- 실습의 첫 프롬프트에 있는 "너는 ○○ 도우미야." 같은 문장은 그 실습에서 코덱스가 맡을 역할입니다.
- 앞 단계에서 내가 답하거나 확인해 준 내용을 전제로 하는 프롬프트가 있습니다. 책의 설명을 함께 읽으며 입력하세요.

## 7장 중요한 문서를 안전하게 만들고 점검하기

### [Do it! 실습] 계약서 초안을 만들고 문서 확인 MCP로 검수하기

VS Code에서 열 폴더: `chapter07/contract`

#### 1. 실습 파일과 작업 폴더를 확인합니다

```text
너는 계약서를 검토하는 리뷰어야. @sample_contract_notes.md와 @sample_contract.txt가 있는지 읽기 전용으로 확인해 줘. 두 파일의 역할과 앞으로 만들 파일을 구분하고, 원본은 수정하지 마.
```

#### 2. 조건 메모에서 합의한 내용을 확인합니다

```text
@sample_contract_notes.md에서 합의된 조건과 [당사자 확인 필요], [법률 전문가 확인 필요] 항목을 나누어 보여 줘. 금액과 날짜는 원문 그대로 적고, 아직 계약서 초안은 만들지 마.
```

#### 3. 초안을 만들 계획을 읽습니다

```text
@sample_contract_notes.md를 근거로 검토용 계약서 초안을 만들 계획을 보여 줘. 출력은 work/contract_draft.md로 정하고, 메모에 없는 조건은 [당사자 확인 필요]로 남겨 줘. 원본 파일을 바꾸지 말고 승인 전에는 새 파일도 만들지 마.
```

#### 4. 계획대로 초안을 만듭니다

```text
확인한 계획대로 work/contract_draft.md를 만들어 줘. @sample_contract_notes.md에 있는 조건만 사용하고 한 조항에는 한 가지 조건만 담아 줘. 당사자 확인이 필요한 항목은 그대로 남기고 sample_contract_notes.md와 sample_contract.txt는 수정하지 마.
```

#### 5. MCP를 연결하고 예제 파일로 테스트를 해봅니다 · MCP 연결 준비

VS Code 터미널에 입력하는 명령입니다. `<server.mjs의 전체 경로>`는 탐색기에서 복사한 경로로 바꿉니다.

```text
codex mcp add document_check -- node "<server.mjs의 전체 경로>"
```

```text
document_check 서버의 check_document를 호출해 줘. relative_path를 sample_contract.txt, missing_document.txt, ../outside.txt로 각각 지정하고 정상 응답과 거부 응답을 구분해 줘. 검사할 파일은 만들거나 수정하지 마. 도구가 없거나 호출에 실패하면 성공으로 기록하지 말고 오류만 알려 줘.
```

#### 6. 새로 만든 초안을 리뷰해봅니다

```text
document_check 서버의 check_document를 relative_path="work/contract_draft.md"로 호출해 줘. 응답의 파일 경로와 표기 후보를 원문 그대로 work/mcp_run_log.json에 기록하고, 네 해석은 별도 항목으로 나누어 줘. 도구는 파일을 수정하지 않으며 work/contract_draft.md도 바꾸지 마.
```

```text
@work/contract_draft.md를 읽기 전용으로 확인해 반복 공백·연속 문장부호·빈 대괄호·용어 표기 차이만 찾아 줘. work/mcp_run_log.json에는 MCP 미연결과 코덱스 읽기 전용 점검을 구분해 기록해 줘. 원문은 수정하지 말고 계약의 효력은 판단하지 마.
```

#### 7. 조건 메모와 초안을 나란히 비교합니다

```text
@sample_contract_notes.md와 @work/contract_draft.md를 비교해 work/contract_review.md를 만들어 줘. 열은 조항 / 근거 메모 / 원래 문장 / 제안 문장 / 확인 주체로 구성해 줘. 새 조건을 확정하지 말고, 지급·해지·손해배상은 당사자 또는 법률 전문가가 확인할 항목으로 표시해 줘.
```

#### 8. 직접 선택한 수정 사항과 이유를 기록합니다

```text
내가 선택한 항목만 work/decision_log.md에 정리해 줘. 열은 조항 / 선택 / 이유 / 남은 확인으로 하고, 아직 선택하지 않은 항목은 보류로 남겨 줘. 초안에 자동 반영하거나 외부로 보내지 마.
```

### [Do it! 실습] 보험증권의 핵심 항목과 확인 질문 찾기

VS Code에서 열 폴더: `chapter07/insurance`

#### 1. 가상 보험증권과 확인 목록을 엽니다

```text

```

#### 2. 확인표에 넣을 항목을 정합니다

```text
@sample_policy.txt와 @insurance_checklist.md를 읽고 insurance_summary.md를 만들 계획을 보여 줘. 열은 항목 / 원문 인용 / 값 / 문서 위치 / 확인 상태로 정해 줘. 보험기간, 납입기간, 보험료, 주계약, 특약, 가입금액, 수익자, 갱신 여부를 포함하고, 찾지 못한 값은 [증권에서 확인되지 않음]으로 표시할 계획만 제안해 줘.
```

#### 3. 계획대로 확인표를 만듭니다

```text
계획대로 insurance_summary.md를 만들어 줘. 숫자·날짜·단위·특약 이름을 원문 그대로 옮기고 문서 위치를 적어 줘. 증권에 없는 내용은 [증권에서 확인되지 않음]으로 남겨 줘. 원본은 수정하지 말고 보험금 지급 가능성, 상품의 유불리, 해지 여부는 판단하지 마.
```

#### 4. 보험사에 물어볼 질문을 만듭니다

```text
@insurance_summary.md에서 확인되지 않은 항목과 약관 확인이 필요한 항목만 골라 questions_for_insurer.md를 만들어 줘. 열은 항목 / 약관 검색어 / 확인할 조항 위치 / 문의 질문으로 정해 줘. 보장 여부를 단정하지 말고 근거 조항과 문서 위치를 확인하는 질문으로 써 줘.
```

#### 5. 원문과 비교하고 남은 확인을 정리합니다

```text
@sample_policy.txt와 @insurance_summary.md를 다시 비교해 insurance_verification.md에 항목별 일치 여부와 남은 확인을 정리해 줘. 보험사 답변은 내가 제공한 내용만 기록하고, 아직 문의하지 않은 항목은 문의 전으로 남겨 줘. 이메일 발송이나 외부 전송은 하지 마.
```
