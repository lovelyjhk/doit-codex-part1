박상담: 질문 후보를 모을 때 표현이 다르지만 같은 답변으로 해결되는 항목은 합치겠습니다. 반대로 안내 메시지를 받지 못한 상황과 메시지는 받았지만 시작 위치를 모르는 상황은 나누겠습니다. 발생 원인과 고객이 할 행동이 다르기 때문입니다. 질문 수를 맞추기 위해 의미가 같은 문장을 반복하지 않겠습니다.

최운영: 초안에는 문장만 있으면 안 됩니다. 어떤 화면이나 안내 자료를 확인했는지도 볼 수 있어야 합니다. 자료를 못 찾았으면 출처를 만들어 적지 말고 '근거 확인 필요'라고 남겨 주세요. 의견을 받았다는 사실과 내용이 검증되었다는 사실도 구분해 주시기 바랍니다.

박상담: 첫 후보는 열 개로 구성하되 실제 문의 빈도로 정한 순서는 아니라는 점을 기록하겠습니다. 순서는 고객이 처음 들어와서 준비하고, 시작하고, 진행 상태를 확인하고, 문제가 생겼을 때 도움을 받는 흐름으로 두겠습니다. 검토 중 중복이 발견되면 질문을 교체하고 교체 이유를 남기겠습니다.

김담당: 최종 검토용 초안도 질문 열 개를 유지하는 것으로 정리하겠습니다. 질문 하나를 빼야 하면 어떤 질문으로 바꿀지 함께 제안하겠습니다. 제목만 열 개 있고 답변이 비어 있는 문서는 완료로 표시하지 않고, 답변 작성과 근거 확인 상태를 각각 적겠습니다.

[가상 확장 기록 3] 질문 1~5의 안내 방식 논의

김담당: 1번은 '처음 안내를 받으면 무엇부터 확인하나요?'로 하겠습니다. 고객이 안내문을 열었을 때 자신에게 해당하는 시작 절차를 찾는 질문입니다. 이 답변이 첫 화면에서 다른 질문으로 들어가는 입구 역할도 할 수 있습니다. 처음부터 모든 문제 해결 방법을 이 답변 하나에 넣지는 않겠습니다.

이기획: 가상 화면 시안에서는 '내 학습'에서 이용할 과정을 찾고 '학습 시작'을 선택하는 흐름을 사용하겠습니다. 이 두 이름은 시안 기준입니다. 초안에는 이름을 넣되 화면 검토 전이라는 상태를 표시하고, 검토하면서 실제 시안과 다르면 문장도 함께 바꾸겠습니다. 버튼의 색이나 위치만으로 설명하지 않겠습니다.

최운영: 좋습니다. '화면 오른쪽에 있는 파란 버튼'처럼 모양에만 기대는 설명은 화면 크기나 표현이 달라지면 알아보기 어렵습니다. 메뉴 이름과 그 메뉴를 선택하는 목적을 함께 적어 주세요. 시작 화면으로 이동했는지 확인하는 문장도 넣고, 이동하지 않았을 때는 8번 문제 해결 질문으로 연결합시다.

박상담: 2번은 '시작하기 전에 무엇을 준비해야 하나요?'로 제안합니다. 가상 예제에서도 고객이 필요한 안내를 확보했는지 확인하는 정도부터 설명하면 좋겠습니다. 별도 프로그램이나 유료 도구가 필수라고 쓰려면 근거가 있어야 합니다. 준비 조건이 확인되지 않았는데 설치부터 요구하면 안 됩니다.

김담당: 준비 항목은 '필수로 확인된 것'과 '아직 확인 중인 것'을 나누겠습니다. 현재 회의 자료만으로 운영체제나 기기 조건을 정할 수는 없습니다. 준비물의 실제 목록을 확인하는 일을 남기고, 확인 전에는 사용 가능한 기기를 임의로 제한하지 않겠습니다. 개인정보를 준비물처럼 요구하는 문장도 넣지 않겠습니다.

이기획: 3번은 '학습할 과정은 어디에서 찾나요?'가 적절하겠습니다. 1번이 첫 행동 전체를 안내한다면, 3번은 과정 목록에서 원하는 과정을 찾는 상황을 다룹니다. 목록에 과정이 나타나는 조건이나 검색 기능의 지원 여부는 화면 시안에서 확인하겠습니다. 확인 전에는 검색창이 있다고 가정하지 않겠습니다.

박상담: 1번과 3번의 중복은 검토 때 다시 보겠습니다. 1번 답변에는 전체 순서를 짧게 쓰고, 과정이 보이지 않는 상황은 3번에서 설명하면 구분될 것 같습니다. 과정이 보이지 않는다는 이유만으로 신청이 실패했다고 단정하지 말고, 확인할 정보와 추가 문의 방법을 안내하는 방향으로 하겠습니다.

김담당: 4번은 '학습을 마쳤거나 진행 중인지 어떻게 확인하나요?'입니다. 완료 상태를 확인하는 방법이 없으면 고객이 같은 절차를 반복할 수 있습니다. 가상 시안에서는 '학습 현황'이라는 이름을 사용하겠습니다. 다만 어떤 행동을 해야 완료로 바뀌는지와 반영 시점은 오늘 정하지 않겠습니다.

최운영: 맞습니다. 끝까지 재생하면 무조건 완료라는 식으로 적지 말아 주세요. 완료 조건은 자료 확인이 필요합니다. 초안에는 '학습 현황에서 표시를 확인한다'는 구조를 쓰고, 표시 이름과 완료 조건은 이기획이 화면과 기준을 확인한 뒤 보완합시다. 확인한 내용이 없으면 질문 4의 검토 상태를 남깁니다.

박상담: 5번은 '로그인이 되지 않으면 무엇을 확인하나요?'로 하겠습니다. 어떤 로그인 방식을 지원하는지는 시안을 확인해야 합니다. 계정이 없다고 바로 판단하거나 고객에게 비밀번호를 보내 달라고 요청하는 안내는 쓰지 않겠습니다. 고객이 선택한 로그인 방식과 화면에 나타난 문구를 기준으로 상황을 정리하도록 하겠습니다.

이기획: 비밀번호 찾기 버튼이나 계정 복구 절차는 현재 검토 자료에서 확인되지 않았습니다. 초안에 기능 이름을 만들어 넣지 않겠습니다. 로그인 화면에서 실제로 제공하는 선택지와 도움말 연결을 확인하겠습니다. 오류 문구를 예시로 넣을 때도 실제 고객 화면 대신 가상 화면을 사용하겠습니다.

김담당: 여기까지 1번 첫 안내, 2번 준비 사항, 3번 과정 찾기, 4번 진행 상태, 5번 로그인입니다. 각 질문의 답변 근거를 확인하고, 서로 연결되는 질문은 번호로 안내하겠습니다. 번호를 바꿀 경우 연결된 답변도 함께 수정해서 다른 질문으로 잘못 이동하는 일이 없도록 하겠습니다.

김담당(가상): 여섯 번째는 “안내 이메일이 오지 않았어요”로 잡겠습니다. 첫걸음 클래스에 처음 들어온 고객이 안내를 받지 못하면 다음 행동을 알기 어렵습니다. 무엇부터 확인하도록 적을까요?

최운영(가상): 그러면 초안에는 주소와 스팸함을 우선 확인한다는 순서까지만 넣읍시다. 화면 위치와 재발송 지원 여부는 확인 필요로 남기고요. 몇 분을 기다리면 온다는 시간도 정하지 맙시다.

이기획(가상): 좋습니다. 재발송 버튼이 있다고 가정한 문장은 빼고, 확인된 경우에만 추가하는 것으로 하죠.
