## 1. 보고서 범위

이 보고서는 가상 팀의 1분기 매출과 다음 분기 보고서 작성 개선안을 정리한 학습용 문서입니다. 대상 기간은 2026년 1월부터 3월까지이며 금액 단위는 만원입니다. 실제 기업의 실적이나 계약 정보가 아닙니다.

분기 매출은 4,500만원입니다. 비용 자료와 전년 같은 기간의 매출은 제공하지 않았습니다. 따라서 이익과 전년 대비 성장률은 이 보고서의 결론에 포함하지 않습니다.

월별 매출, 제품별 매출과 고객 분류별 매출은 같은 분기 실적을 서로 다른 기준으로 묶은 값입니다. 각 표의 합계가 같더라도 표끼리 금액을 더하면 거래를 중복 집계하게 됩니다. 요약에서는 전체 규모를 먼저 제시하고 구성별 설명을 이어가는 방식을 사용합니다.

이 자료의 활용 목적은 기존 매출을 점검하고 보고서 작성 시험의 범위를 결정하는 것입니다. 투자 판단이나 확정 예산을 위한 근거 자료는 포함되어 있지 않습니다. 업무에 적용하려면 사용할 거래 명세, 집계 기준과 검토 책임자를 별도로 확인해야 합니다.

## 2. 월별 매출

월별 매출은 1월 1,200만원, 2월 1,500만원, 3월 1,800만원입니다. 세 달을 합하면 4,500만원으로 분기 합계와 같습니다. 각 월의 차이는 300만원입니다.

이 추이만으로 계절 효과나 광고의 성과를 입증할 수는 없습니다. 거래별 원인이나 외부 환경 자료가 없기 때문입니다. 월별 증가의 원인은 확인이 필요합니다.

월별 금액은 각 달의 매출이며 연초부터 누적한 값이 아닙니다. 추이를 그림으로 보여 줄 때에는 월 순서를 유지하고 같은 단위를 사용해야 합니다. 이전 달과의 금액 차이를 설명할 수는 있지만, 그 차이를 특정 활동의 성과라고 표현하려면 추가 근거가 필요합니다.

월별 변화의 이유를 살피려면 거래일, 품목, 판매 경로와 조정 내역을 같은 기준으로 모으는 방안을 검토할 수 있습니다. 현재는 해당 상세 자료를 제공하지 않았습니다. 다음 보고서에서도 원인을 확인하지 못했다면 금액의 변화와 원인 미확정을 구분해 기록합니다.

## 3. 제품별 구성

제품 A의 분기 매출은 2,400만원, B는 1,500만원, C는 600만원입니다. 세 제품의 합계는 4,500만원입니다. 제품 A가 제공된 제품군 가운데 가장 큰 매출을 차지합니다.

제품별 비용은 제공하지 않았습니다. 매출이 크다는 이유로 이익도 가장 크다고 판단하지 않습니다. 다음 분기의 제품별 목표와 판매 계획 역시 확정하지 않았습니다.

제품별 비교는 판매 수량이나 단가가 아니라 매출액 기준입니다. 제품 A의 매출이 가장 크다는 사실만으로 가장 많이 팔린 제품이라고 설명할 수는 없습니다. 수량과 단가가 서로 다를 수 있으므로 판매 방식에 대한 해석은 자료를 받은 뒤 검토해야 합니다.

다음 분석을 위해 제품별 판매 수량, 반품 반영 방식과 비용 항목을 확인하는 안을 제안합니다. 자료를 받으면 비교 대상의 기간과 제품 분류가 현재 보고서와 같은지도 살펴야 합니다. 그전에는 제품별 수익성 순위나 판매 확대 효과를 확정하지 않습니다.

## 4. 고객 분류

신규 고객 매출은 1,000만원이고 기존 고객 매출은 3,500만원입니다. 두 범주의 합계는 4,500만원입니다. 이 가상 자료에서는 첫 거래 분기가 이번 1분기이면 신규 고객으로 분류합니다.

고객 수와 개별 고객 명세는 포함하지 않았습니다. 거래 규모만으로 위험 고객을 정하지 않습니다. 위험의 의미와 판단 조건을 정의하지 않았으므로 위험 고객 수는 확인 필요입니다.

신규·기존 분류는 거래 이력이 시작된 시점을 기준으로 합니다. 같은 고객의 이번 분기 거래가 여러 건이어도 고객 수를 셀 때와 매출을 합산할 때의 방식은 달라집니다. 이번 표는 고객별 거래 명세를 담지 않았으므로 거래 건수나 고객당 매출로 해석하지 않습니다.

고객 위험을 분석하려면 어떤 상태를 위험으로 볼지 먼저 정해야 합니다. 미수금, 거래 중단 또는 계약 변경처럼 확인하려는 문제가 다르면 필요한 자료도 달라집니다. 현재 자료만으로 특정 고객을 위험하다고 표시하는 대신 판단 기준과 추가 자료를 요청합니다.

## 5. 반품 처리

확정 반품 100만원은 이미 3월 매출에서 차감했습니다. 1,800만원이라는 3월 수치는 이 반품을 반영한 금액입니다. 분기 합계를 계산하면서 100만원을 다시 빼면 중복 차감이 됩니다.

보고서를 읽는 사람이 총액과 조정액의 관계를 이해할 수 있도록 반품 처리 기준을 함께 남깁니다. 새로운 정정이 확인되면 기존 원본을 덮어쓰기보다 수정한 집계 버전을 구분하는 방식을 제안합니다.

월별 매출을 다른 보고서로 옮길 때에는 반품을 차감한 금액이라는 설명도 함께 옮깁니다. 조정 전 금액과 조정 후 금액을 구분하지 않으면 요약 담당자가 반품을 다시 처리할 수 있습니다. 이번 실습에서는 제공된 월별 금액을 그대로 합산하는 기준을 유지합니다.

후속 확인에서는 반품 거래의 원래 매출과 실제 반영한 달을 대조하는 방법을 제안합니다. 해당 거래 명세는 현재 자료에 없으므로 개별 거래의 회계 처리를 검증했다고 표현하지 않습니다. 추가 정정이 발생하면 사유와 영향을 받는 기간을 새 보고서에 남깁니다.

## 6. 확인할 거래

큰 금액 거래 1건을 추가 확인할 계획입니다. 이 문서에는 해당 거래의 번호와 금액을 넣지 않았습니다. 가장 큰 거래가 오류라고 확정하거나 합계에서 임의로 빼면 안 됩니다.

이 거래의 근거, 확인 담당자와 완료 시점은 미정입니다. 확인 항목을 보고서의 별도 목록에 기록하는 안을 제안합니다. 거래가 정상인지 정정 대상인지는 원자료를 확인한 뒤 판단해야 합니다.

큰 거래는 확인 대상이라는 상태만 기록합니다. 거래의 크기와 오류 여부는 다른 판단이므로 담당자가 원자료를 확인하기 전에는 삭제나 금액 보정을 진행하지 않습니다. 확인 전 보고서에는 현재 합계가 어떤 자료를 기준으로 계산되었는지 설명하는 것이 필요합니다.

거래 확인 목록에는 원자료를 찾을 단서, 질의 내용과 회신 결과를 구분해 남기는 방식을 제안합니다. 실제 거래 번호와 담당자가 정해지지 않은 칸은 비워 두거나 확인 필요로 표시합니다. 회신을 받으면 기존 설명과 달라진 점을 기록한 뒤 집계에 미치는 영향을 검토합니다.

## 7. 현재 작성 방식

현재 가상 팀의 작성 방식은 자료 취합, 월별 합계 계산, 사람이 결과 대조, 보고서 문장 작성의 순서입니다. 계산을 확인하기 전에 해석 문장부터 작성하지 않도록 하는 흐름입니다.

실제 작업 시간과 재작업 횟수는 측정하지 않았습니다. 자동화를 제안한다는 이유로 시간을 절반으로 줄인다고 쓰지 않습니다. 효과를 비교하려면 동일한 업무 범위에서 측정 기준부터 정해야 합니다.

자료를 취합할 때에는 서로 다른 파일에서 같은 거래가 반복되지 않는지 확인할 수 있어야 합니다. 계산 단계에서는 사용한 파일과 포함한 기간을 남기는 방식을 제안합니다. 검토자가 합계를 다시 계산할 수 있어야 보고서 문장에 적힌 숫자도 원자료로 되짚을 수 있습니다.

작업 시간을 비교하는 시험을 진행한다면 자료 준비, 합계 계산, 결과 대조와 문장 작성의 시작과 끝을 구분해 기록할 수 있습니다. 이 기록 방법은 후속 측정을 위한 제안입니다. 현재 과정에 소요된 시간이나 개선 후 절감 효과를 측정한 결과는 없습니다.

## 8. 자동화 제안

첫 시험은 월별 합계와 누락값 목록 생성으로 한정하는 안입니다. 외부 전송, 원본 삭제, 자동 결재는 이번 제안 범위에서 제외합니다. 가상 자료의 복사본에서만 시험합니다.

성공 기준으로는 결과 합계와 원본 합계의 일치, 빈 값을 0으로 바꾸지 않는 처리, 사용한 입력 파일 확인을 제안합니다. 실제 도입 여부와 구현 도구는 아직 결정하지 않았습니다.

시험 결과에는 월별 합계와 별도로 확인할 빈 값을 남기는 방법을 제안합니다. 합계만 맞았다는 이유로 누락 자료가 해결되었다고 판단하면 안 됩니다. 입력 자료의 상태를 검토자가 알 수 있어야 계산 결과를 확정할지, 추가 자료를 기다릴지 결정할 수 있습니다.

시험을 시작하기 전에는 입력 파일, 결과 파일 이름과 원본 보존 방식을 정합니다. 결과가 예상과 다르면 사용한 복사본과 계산 기준을 확인하고 필요한 부분만 다시 실행합니다. 외부 시스템에 결과를 반영하거나 실제 업무 절차를 바꾸는 일은 별도의 검토 대상으로 남깁니다.

## 9. 일정 제안

1주차에는 입력 양식과 확인 기준을 정하고, 2주차에는 복사본으로 계산을 시험하며, 3주차에는 사람이 결과를 대조하는 안입니다. 달력상의 착수일은 정하지 않았습니다.

담당 인원과 시험 데이터 양, 최종 승인자와 완료일은 미정입니다. 기간을 계획했다고 실행 가능성이 증명된 것은 아닙니다. 각 단계의 결과를 확인한 뒤 다음 단계로 진행할지 판단해야 합니다.

일정의 각 단계는 앞 단계에서 확인한 기준을 다음 작업에 넘기는 흐름입니다. 입력 양식이 정리되지 않은 상태에서는 계산 시험을 시작해도 어떤 값이 맞는지 판단하기 어렵습니다. 단계가 끝날 때 준비된 자료와 남은 질문을 기록하는 방식을 제안합니다.

원자료 확보가 늦어지거나 담당자가 정해지지 않으면 제안한 순서대로 진행하기 어려울 수 있습니다. 이 경우에는 시험 범위를 줄일지 일정 변경이 필요한지 먼저 검토합니다. 달력 날짜와 인원 배치는 실제 참여자의 가능 시간을 확인한 뒤 확정해야 합니다.

## 10. 리스크와 대응

입력 누락은 합계 확정을 막을 수 있습니다. 누락값을 따로 표시하고 담당자에게 확인하는 대응을 제안합니다. 반품의 중복 차감은 과소 집계의 원인이 될 수 있으므로 반영 여부를 확인합니다.

도입 비용과 운영 책임, 업무 자료에 적용할 내부 규정도 확인할 항목입니다. 이 문서는 규정 준수나 보안을 검증한 보고서가 아닙니다. 실습은 개인정보가 없는 가상 자료만 사용합니다.

누락과 중복 차감은 서로 다른 방식으로 결과에 영향을 줍니다. 누락은 계산 대상이 충분한지 확인하게 하고, 중복 차감은 같은 조정이 반복 반영되었는지 확인하게 합니다. 두 항목을 모두 일반적인 데이터 오류로 묶기보다 원자료에서 확인할 질문을 나누어 기록합니다.

운영 단계에서 오류가 발견되었을 때 누구에게 알리고 어느 결과를 다시 만들지도 정할 필요가 있습니다. 이는 도입 전 준비 항목이며 이미 마련된 대응 체계는 아닙니다. 비용과 책임 범위가 확인되기 전에는 계속 사용할 수 있는 운영 환경이 확보되었다고 쓰지 않습니다.

## 11. 검토와 승인

작성 역할과 검토 역할을 나누는 안을 제안합니다. 작성자는 사용한 자료와 계산 기준을 남기고, 검토자는 수치와 미정 항목을 원본에 대조합니다. 사람 이름과 승인 일정은 확정하지 않았습니다.

한 페이지 요약을 만들 때에는 4,500만원 합계, 주요 구성, 반품 반영, 시험 범위, 의사결정에 필요한 미정 항목을 남기는 것이 적절합니다. 전체 원문을 읽지 않아도 결정에 필요한 제한을 알 수 있어야 합니다.

검토자는 합계뿐 아니라 제목과 문장이 숫자의 범위를 정확히 설명하는지도 확인합니다. 매출을 이익으로 바꾸어 쓰거나 제안한 일정을 확정 일정처럼 표현한 경우에는 문장을 수정해야 합니다. 작성자가 바꾼 위치와 수정 사유를 남기면 검토 결과를 다시 확인하기 쉽습니다.

미정 항목이 남아 있을 때에는 무엇이 확보되어야 승인을 판단할 수 있는지 함께 적는 방안을 제안합니다. 작성 완료와 업무 적용 승인을 같은 상태로 처리하지 않습니다. 실제 승인 여부와 승인 담당자는 제공 자료에 없으므로 후속 회의에서 정할 항목으로 남깁니다.

## 12. 의사결정 항목

현재 요청할 결정은 가상 복사본에서 월별 합계와 누락값 목록 생성 시험을 진행할지 검토하는 것입니다. 전체 업무 자동화를 승인하는 요청이 아닙니다. 담당자와 착수일을 정해야 실행 계획이 구체화됩니다.

전년 비교, 이익, 위험 고객 수, 절감 시간, 도입 비용은 여전히 확인 필요입니다. 이 제한을 숨기지 않고 먼저 자료를 요청해야 합니다. 수치가 없는 지표를 0이라고 쓰거나 추정 성과로 채우지 않습니다.

의사결정자에게는 현재 확인된 매출, 남은 자료의 한계와 복사본 시험 제안을 함께 제시합니다. 시험을 진행하기로 결정하더라도 매출 개선 효과나 전체 업무 도입까지 승인한 것으로 해석하지 않습니다. 결정된 범위와 추가 확인 조건을 분리해 남겨야 다음 작업이 명확해집니다.

후속 회의에서는 시험 담당자, 시작 가능한 시점과 원자료 확보 방법을 우선 확인하는 안을 제안합니다. 결정을 보류한다면 부족한 자료와 다시 검토할 조건을 기록할 수 있습니다. 이 보고서에는 아직 회의 결과가 없으므로 선택된 방안이나 승인 일자를 새로 채우지 않습니다.
